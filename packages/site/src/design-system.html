cdz-button

Estados: default, hover (interactivo), focus-visible (tab) y disabled.

Default Disabled

cdz-input

Estados: default, con helper text, required, error y disabled.

cdz-checkbox

Estados: default, checked, indeterminate, error y disabled.

cdz-radio

Estados: default, checked, error y disabled.

Demostración honesta de una limitación real: estos dos comparten name="plan" pero marcar uno no desmarca al otro — cada <cdz-radio> vive en su propio shadow root, y la agrupación nativa de radios no cruza esa frontera. La coordinación real (exclusión mutua, flechas del teclado) es trabajo de una futura molécula cdz-radio-group, no de este átomo.

cdz-text

as (tag semántico) y size (estilo visual) son independientes.

Tamaño por defecto según el tag (as="h3") Un párrafo normal (as="p", size="body-md" por defecto). Texto de apoyo más chico (size="body-sm").

El punto central: un <h2> real para la estructura del documento, pero que visualmente no grita — útil para un subtítulo que debe seguir la jerarquía de encabezados sin verse enorme.

cdz-select

Estados: default con placeholder, helper text, required + error, disabled. options se pasa como propiedad JS (no como atributo) — ver main.ts.

cdz-textarea

Estados: default, con helper text, required, error y disabled.

cdz-switch

Estados: apagado, encendido, helper text, error y disabled (en ambas posiciones). role="switch" sobre un <input type="checkbox"> nativo — ver el JSDoc del componente.

cdz-range

Estados: default, con helper text, error, disabled, y min/max/step distintos. Sin required a propósito — un range nunca está "vacío".

cdz-file-input

Estados: default, con accept, multiple, helper text, required + error, y disabled. El texto visible lo dibuja el componente (no el navegador) para que el idioma lo controle la app — ver el JSDoc.

cdz-link

Siempre subrayado (WCAG 1.4.1: el color no puede ser la única señal). target="_blank" agrega rel="noopener" y un aviso para lectores de pantalla automáticamente.

Un enlace vive dentro del texto y hereda su tipografía, por eso no rompe el renglón ni cambia de tamaño. Este otro abre en una pestaña nueva — fíjate en el ícono, y prueba con un lector de pantalla para oír el aviso.

También sirve para descargas: bajar esta página.

cdz-icon

SVG desde un registro compartido, nunca icon font — ver ADR-0016. El color sale de currentColor, así que el ícono toma el color del texto donde esté.

Escala: sm, md (por defecto) y lg.

Decorativo vs. significativo: por defecto el ícono es decoración y queda oculto para lectores de pantalla, porque casi siempre está al lado de un texto que ya dice lo mismo. Solo cuando le pasás label pasa a ser significativo (role="img" + aria-label) — para cuando el ícono es lo único que comunica esa información.

Hereda el color: en contexto de error , y en texto normal.

cdz-badge

Primer componente con variantes semánticas, y el que obligó a expandir la paleta: no había verde ni ámbar en el sistema. Los 20 pares texto-sobre-fondo están verificados en ambos modos — ver ADR-0017.

Borrador Información Completado Atención Fallido

El ícono refuerza, no es lo que hace accesible al badge. El texto ya es señal no cromática: "Completado" y "Fallido" se distinguen sin ver ni color ni ícono. Lo que suma el ícono es una señal de forma que sobrevive al escaneo — en una lista larga, alguien que no separa los tonos igual recibe una pista por fila sin leer cada etiqueta. Viene por defecto y se saca con hide-icon, no al revés:

cdz-spinner

Indicador de carga indeterminado. A diferencia de cdz-badge, este sí es una live region (role="status", polite): un badge ya está cuando carga la página, un spinner aparece porque algo empezó — ver ADR-0018.

cdz-progress

Progreso determinado, sobre <progress> nativo: el navegador deriva role="progressbar" y los valores ARIA de value/max, sin escribir un atributo a mano. El indeterminado es cdz-spinner, no este — ver ADR-0019.

cdz-tooltip

El último de Feedback, y el más difícil de hacer accesible. Se abre con el mouse y con el teclado, se cierra con Escape, y puedes mover el puntero sobre el propio tooltip sin que desaparezca — los tres requisitos de WCAG 1.4.13. Ver ADR-0020.

Enviar informe Descripción larga

Prueba con el teclado: presiona Tab hasta llegar a los botones de arriba y el tooltip aparece de inmediato, sin la espera que sí tiene el mouse. Esa espera existe para que pasar el puntero por encima de varios controles no dispare un tooltip por cada uno.

El texto va como propiedad, no como slot, a propósito: un tooltip no puede contener nada interactivo, porque no se puede llegar a él con Tab. Si necesitas botones o enlaces flotantes, eso es un cdz-popover, no un tooltip.

cdz-divider

Decorativo por defecto, semántico solo si se pide. <hr> significa "corte temático", pero la mayoría de las líneas de una interfaz son mobiliario visual: anunciar "separador" una vez por fila convierte una lista en ruido. Ver ADR-0021.

Horizontal, decorativo — el caso común:

Vertical, para separar elementos en una fila. Se estira solo a la altura de sus hermanos dentro de un contenedor flex:

Perfil Ajustes Salir

No trae margen propio, a propósito: el espacio entre el divisor y lo que lo rodea le corresponde al layout que contiene a ambos, no al divisor. Es la misma razón por la que ningún otro átomo se pone márgenes a sí mismo.

cdz-avatar

Tres formas de dibujarse, en orden: la foto de src; si falla, las iniciales sacadas de name; y si no, un ícono genérico de persona. Cuál de las dos últimas se usa lo decide fallback, y las dos son opciones legítimas: las iniciales dicen qué persona, el ícono dice una persona. Ver ADR-0022.
